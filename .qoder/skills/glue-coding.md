# 胶水编程技能 (Glue Coding)

> **核心理念：能抄不写，能连不造，能复用不原创。**

## 触发条件

当用户说以下话时，启用此技能：
- "帮我找个轮子做XXX"
- "有没有现成的库可以用"
- "我要快速搭建一个XXX"
- "把XXX和YYY连起来"
- "不想造轮子"
- "有什么成熟方案"

## 核心原则（铁律）

```
❌ 禁止从零写代码（幻觉根源）
❌ 禁止重复造轮子（复杂性根源）
❌ 禁止修改开源库源码（维护噩梦）

✅ 只复用成熟的、生产验证的开源项目
✅ AI只负责：理解意图 → 连接模块
✅ 用户只需要：说清楚输入和输出
```

## 架构模型

```
┌─────────────────────────────────────────────────────┐
│                    用户的业务需求                      │
│              "我要实现XXX功能"                        │
└─────────────────────────────────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────┐
│                   AI 胶水层 (Glue Layer)              │
│                                                      │
│   职责：理解需求 → 找轮子 → 写连接代码                  │
│   产出：50行胶水代码，而不是3000行原创代码              │
│                                                      │
└─────────────────────────────────────────────────────┘
                           │
          ┌────────────────┼────────────────┐
          ▼                ▼                ▼
   ┌─────────────┐  ┌─────────────┐  ┌─────────────┐
   │  成熟模块 A  │  │  成熟模块 B  │  │  成熟模块 C  │
   │  (官方SDK)   │  │  (10k+ ⭐)   │  │  (生产验证)  │
   └─────────────┘  └─────────────┘  └─────────────┘
```

## 执行流程

### 步骤1：明确需求
用户用一句话描述目标：
- "我要把Telegram消息存到数据库"
- "我要定时抓取网页数据"

### 步骤2：拆解需求 → 找轮子
AI分析需求，搜索成熟方案：

```
提示词模板：
我需要实现 [用户需求]，请帮我：
1. 分析涉及哪些技术领域
2. 搜索GitHub上成熟的开源库（优先10k+星、官方SDK）
3. 对比推荐最稳定的方案
4. 给出GitHub Topics链接供我确认
```

### 步骤3：理解接口
把官方文档喂给AI，总结：
- 输入是什么
- 输出是什么
- 调用方式

### 步骤4：编写胶水代码
AI只写连接代码：
- 封装接口
- 数据转换
- 错误处理
- **绝不修改原库**

### 步骤5：验证运行
- 跑通 → 完成
- 报错 → 把错误扔给AI，继续粘

## 找不到合适轮子怎么办？

> **超市没有你要的菜？别急，有应对策略！**

### 决策流程图

```
找轮子
   │
   ├── 找到完美匹配 ──▶ 🎉 直接用！
   │
   ├── 找到80%匹配 ──▶ ✅ 用它 + 20%胶水补齐
   │
   ├── 找到多个小轮子 ──▶ ✅ 组合起来用
   │
   ├── 只找到周边轮子 ──▶ ⚠️ 核心自己写 + 周边复用
   │
   └── 完全没有 ──▶ 🤔 换关键词再搜 / 调整需求 / 最小原创
```

### 策略1：换个关键词找找

**生活例子：** 番茄区没了 → 去圣女果区看看

**编程世界：**
```
"微信消息推送" 没找到
→ 换词："wechat bot"、"weixin api"、"企业微信SDK"
```

**技巧：让AI帮你生成5-10个同义关键词搜索**

### 策略2：80%匹配 + 20%胶水

**生活例子：** 没有红烧肉调料包 → 买酱油+糖+八角自己配

**编程世界：**
```
找到一个80%匹配的库
→ 核心功能用它
→ 缺的20%自己写胶水补上
```

**原则：80%复用 + 20%原创 = 还是比从零写强10倍**

### 策略3：小轮子组合成大轮子

**生活例子：** 没有火锅套餐 → 分开买底料+牛肉+蔬菜

**编程世界：**
```
需求：语音转文字+翻译成英文

没有一站式方案？
→ 轮子1：whisper（语音→文字）
→ 轮子2：deep-translator（中→英）
→ 胶水：10行代码串起来
```

### 策略4：核心自己写，周边用轮子

**生活例子：** 独家配方自己做，锅铲火用现成的

**编程世界：**
```
核心算法太独特，没有现成库
→ 核心逻辑自己写（不可避免）
→ 周边全部复用：
  - 网络请求 → httpx
  - 数据验证 → pydantic
  - 日志记录 → loguru
  - 配置管理 → python-dotenv
  - 命令行 → typer
```

**原则：只原创"独特的核心"，其他全部复用**

### 策略5：调整需求

**生活例子：** 想吃龙虾但太贵 → 改吃小龙虾也很香

**编程世界：**
```
需求太小众，完全没轮子
→ 思考：能不能用现有轮子换个方式实现？
→ 或者：需求是否可以微调，适配现有方案？
```

### 复用优先级

```
1️⃣ 找完美匹配的轮子 → 直接用          (最佳)
2️⃣ 找80%匹配的轮子 → 用它+补胶水      (很好)
3️⃣ 找多个小轮子组合 → 串起来          (好)
4️⃣ 核心自己写+周边用轮子 → 最小原创   (可接受)
5️⃣ 完全自己写 → 最后手段              (尽量避免)
```

### 复用比例参考

| 复用比例 | 评价 |
|----------|------|
| 100%复用 | ✅✅✅ 最佳（但很少能做到） |
| 95%复用 + 5%原创 | ✅✅ 很好 |
| 80%复用 + 20%原创 | ✅ 可接受 |
| 50%复用 + 50%原创 | ⚠️ 勉强 |
| 100%原创 | ❌ 最差（违背胶水编程精神） |

## 项目结构模板

```
项目根目录/
├── requirements.txt     # 依赖声明（指向成熟库）
├── glue/                # 胶水代码（你的代码只在这里）
│   ├── __init__.py
│   ├── connectors/      # 连接器（A→B的转换）
│   └── main.py          # 入口
├── config/              # 配置
└── docs/                # 说明
```

| 需求 | 推荐轮子 | 星数 |

## 质量检查

完成前确认：
- [ ] 是否复用了成熟库？（不是自己写的）
- [ ] 胶水代码是否少于100行？
- [ ] 是否修改了原库代码？（应该是否）
- [ ] 是否有清晰的输入→输出？

## 记住

> **最好的代码是不写代码。第二好的是胶水代码。**
>
> *"The best code is no code at all. The second best is glue code."*
